# Accessibility pass (W4b)

> Written against the Vaadin frontend. Since D-033 the pages are Qute templates with native controls; CSS and JS live in
> `backend/src/main/resources/META-INF/resources/` and `ThemeContrastTest` in
> `backend/src/test/java/dev/rabauer/ai/diary/web/ui/`. Findings 1 to 8 were carried over (same rules, same tests);
> the Vaadin-specific items (Lumo focus ring, shadow parts) no longer exist. The text below is kept as the record of that pass.

Scope: SPEC section 12 (WCAG 2.1 AA contrast, labels, visible focus, full keyboard use, `prefers-reduced-motion`) and
section 13. Behaviour is unchanged; only accessibility defects were fixed.

## What was checked

Method: backend with the `test` profile (H2, fake providers), frontend in dev mode, Chromium in the Browser pane.
Per page an injected script walked the DOM including shadow roots and reported headings, landmarks, unnamed
buttons/links/inputs, text contrast (computed colours, 4.5:1 / 3:1 large), positive `tabindex`, images without `alt`
and horizontal overflow. Keyboard behaviour was exercised by hand (Tab order, skip link, focus ring, focus after
actions). Code was reviewed for the custom elements and for reduced-motion handling.

| Page | Light | Dark | 375px |
|---|---|---|---|
| Today (`/`) | scripted audit + manual | scripted audit + manual | overflow + target size |
| Journal list (`/entries`) | audit | audit | overflow |
| Entry detail (`/entries/{id}`) | audit | audit | overflow (defect found, fixed) |
| Coach start + error state | audit | audit | overflow |
| Memory | audit | audit | overflow |
| Thinking Gym (picker, exercise) | audit | audit | overflow |
| Weekly (empty state) | audit | audit | overflow |
| Settings | audit + focus ring screenshots | audit + screenshots | overflow |

Not reachable without an LLM/microphone in the test setup: the coach conversation with messages, memory review and
candidate cards, a weekly report, a running recording. Those were checked by code review only (see below).

## Findings and fixes

| # | Finding | Fix |
|---|---|---|
| 1 | Today, Journal, Entry detail and Coach had no `h1` (first heading was `h2`; Today skipped `h2` to `h3`). | `h1` page titles, sections are `h2`. The coach "current question" box is `h2`. |
| 2 | Lumo draws all focus rings with `--lumo-primary-color-50pct` (50% alpha accent, about 2.4:1 on the page). | Token is the solid accent (`styles.css`); `ThemeContrastTest.focusRingTokenIsTheSolidAccent` guards it. |
| 3 | Text fields, text areas, selects and checkboxes had only a faint fill as boundary (about 1.1:1, WCAG 1.4.11). | 1px `--diary-border` boundary (3:1 verified by `ThemeContrastTest`), error colour when invalid, accent when a checkbox is checked. |
| 4 | Destructive primary buttons use `--lumo-error-contrast-color` on the error fill; not covered by the contrast test. | Test now checks it in light and dark. |
| 5 | `<diary-recorder>`: `role="meter"` without `aria-valuenow` inside an `aria-hidden` block; `aria-pressed` on a button whose label also flips Pause/Resume (double signal). | Both removed; the live status text carries the state. Button borders use the 3:1 border token. |
| 6 | Keyboard focus was dropped to `<body>` when the focused button was hidden or disabled: recorder (Record to Pause/Stop and back), answer recorder (Stop to Cancel to Record), "Stop audio" in the coach, coach Pause/Resume/End (controls are rebuilt), coach error retry, Finish on Today and on the entry detail page (page is rebuilt), Journal Previous/Next (pager rebuilt). | Focus is moved to the next sensible control (recorder buttons, answer field after stopping audio, first coach control, retry button, page heading, same pager button). Recorder logic does not steal focus if the user already moved elsewhere. |
| 7 | Journal cards, today's entries were visually lists but not list semantics; the pager had no landmark name. | `role=list`/`listitem` with labels, pager is a labelled `navigation` (new keys `entries.journal.listLabel`, `entries.journal.pager` in en and de). |
| 8 | Entry detail overflowed horizontally at 375px (footer button row did not wrap, reflow WCAG 1.4.10). | `flex-wrap` on the detail head/footer and journal head/pager. |
| 9 | Reduced motion: shadow-DOM animations of Vaadin parts (progress bar, dialog overlays, notification) are not reached by `*` rules. | Explicit `::part()` rules inside `prefers-reduced-motion: reduce`. The recorder already switches the waveform to a level bar (new JS test `waveform.test.mjs`) and stops the pulse. |

New automated checks: `I18nKeysTest` (every literal translation key passed to `getTranslation`/`texts.get` exists
non-blank in both bundles, recorder/voice/skip labels exist, en and de bundles have identical key sets),
`ThemeContrastTest` extensions, `waveform.test.mjs`.

## Verified as already good

Skip link (first focusable, moves focus to `main`), one named `nav` with `aria-current="page"`, `main` landmark,
`lang` on `<html>`, unique page titles per route, icons `aria-hidden`, every Vaadin field labelled, live regions
(`role=status` polite, errors `role=alert`), `<time datetime>` in the coach, native `<audio controls>` with label,
heading focus after exercise/review changes in Gym and Memory, Escape cancels a voice answer, no positive
`tabindex`, no keyboard traps found, 44px minimum recorder buttons, no colour-only signals.

## Remaining issues (not fixed)

- Inline links in lists are 22px high (WCAG 2.1 has no target-size AA criterion; 2.2 AA asks 24px). Left as is.
- Bottom navigation labels are 0.65rem on phones; readable but small. Left to the design owner.
- The Today language select is narrow at about 1000px and truncates "Automatisch erkennen" (visible text, name intact).
- Disabled controls (for example "Delete everything" before the phrase is typed) are exempt from contrast rules and
  stay muted by design.
- The Vaadin Copilot dev overlay in dev mode is not part of the production build and was ignored.

## Not checked

- Real screen readers (NVDA, VoiceOver, TalkBack): announcements are inferred from roles and live regions only.
- Automated axe/Lighthouse scan: no third-party code was downloaded; the scripted audit above is a partial substitute.
- The coach conversation, memory review, weekly report with content, and a live recording with a microphone.
- The recorder and answer-recorder focus logic was reviewed and unit-syntax checked, not exercised with a microphone.
- Windows high-contrast mode and 200%/400% zoom beyond the 375px reflow check.

## Qute UI pass (2026-11-24)

Scope: the server-rendered UI after D-033 (pages `/`, `/journal`, `/journal/{id}`, `/journal/{id}/reflect`, `/memory`,
`/gym`, `/weekly`, `/settings`), against the checklist above (WCAG 2.1 AA).

### Method
- Backend from the packaged jar with a throwaway H2 file, fake providers and a handful of seeded entries (two finished);
  Chromium in the Browser pane.
- A small in-page checker (written for this pass, no downloaded code) walked each page and reported: heading list,
  landmarks and their labels, unnamed links/buttons/fields, fields without a label, unhidden SVGs, live regions,
  duplicate ids, dangling `aria-*` references, horizontal overflow, text contrast from computed colours (4.5:1, 3:1 for
  large text, alpha blended over the real background chain) and interactive elements under 24 px.
- A second script measured non-text contrast (field and segmented-control borders against their parent).
- Keyboard by hand: real Tab presses, `document.activeElement` and the computed outline after each press; skip link;
  the delete dialog (`confirm.js`: focus trap, Escape, focus returns to the opener); coach start and its error state;
  journal search with Enter; settings validation.
- Reflow: 1280, 375 and 320 px in light and dark; text-only 200% (root font size) at 320 px.
- No JavaScript: `curl` against the pages and every form route (journal search GET, settings POST with and without
  `_csrf`, Today POST, entry delete form present, week create form present). `lang` per `Accept-Language`.
- Code review for what the fake providers cannot produce (coach conversation, memory review, weekly report, recording).

The scan ran on all eight pages in light and dark at 1280 px and in dark at 320 px (light at 320 px only for the 200% test) with no findings from the contrast and structure
scan. Every page has one `h1`, no skipped levels, one labelled `nav`, one `main`, no duplicate ids, no dangling
references, no unnamed controls, no inline script/style.

### Defects found and fixed
| # | Finding | Fix |
|---|---|---|
| 1 | The phone tab bar was `position: fixed`; with large text (200%) its five items overflowed the width and the bar grew over the content (the reserved bottom padding was a fixed guess). | The bar is now in the flow (flex column, `order: 2`, sticky at the bottom), its list wraps, labels may break anywhere; no reserved padding needed. Item height 3.5rem. |
| 2 | Digit keys 1 to 4 graded a memory card from anywhere on the page while the answer was revealed (WCAG 2.1.4 Character Key Shortcuts, level A: speech input and accidental presses). | The shortcut only works while focus is inside the revealed card (focus moves there on reveal); the hint text says so (en, de). |
| 3 | The settings interval error is injected by script into a paragraph that was not a live region, so a screen reader user (focus stays on the field) heard nothing. | `role="alert"` on `#settings-intervals-error`. |
| 4 | Settings checkboxes were 22 px (below the 24 px that WCAG 2.2 asks). | 1.5rem. |
| 5 | Large text overflowed horizontally: gym category cards (`minmax(15rem,1fr)`), memory tiles, the journal filter pills, the entry layout grid (long buttons). | `minmax(min(15rem,100%),1fr)`, `minmax(0,1fr)`, wrapping filter, `min-width: 0` on grid children, `overflow-wrap: anywhere` on titles. |

Regression tests: `AccessibilityMarkupTest` (one h1, `lang` en/de, labelled nav, one main, skip link first and targeting
`main`, unique ids and resolving `aria-*` references, no inline script/style/handlers, every field labelled, the alert
role, tab bar not fixed and wrapping, grade shortcut scoped to the card).

### Verified as already good
Skip link first and working (focus moves to `main`), focus ring 2.4 px solid accent on every control in both themes
(recorder and speech elements use their own 3 px text-colour ring in the shadow DOM), `aria-current="page"` on exactly
the active nav link, `aria-pressed` on the Today mode and theme buttons, `aria-expanded` on the memory tiles and the gym
timer, status and alert regions each present once with distinct ids and one polite notification region, decorative
icons `aria-hidden`, `lang` from `Accept-Language` (en, de, else en) and the UI language setting, native `<dialog>`
with `aria-labelledby`/`describedby`, destructive dialog starts on Cancel, journal search announces its result count
once, field borders 3.2:1 (light) and 4.2:1 (dark) or better, focus moved to headings or the next control after every
in-place update, `prefers-reduced-motion` rule for all light-DOM animation plus explicit rules in the shadow-DOM
elements, noscript fallbacks (Today and settings forms, journal GET search).

### Known limitations and open points
- No real screen reader was run (NVDA, VoiceOver, TalkBack); announcements are inferred from roles and live regions.
- A recording with a real microphone was not possible; the recorder and answer recorder are covered by the earlier
  code review and unit tests only. No real Raspberry Pi: nothing here says anything about performance on the Pi.
- The coach conversation with messages, memory review cards, candidates and a weekly report with content need a real
  LLM; their markup was reviewed in the templates and scripts, not exercised in the browser.
- Journal and timeline excerpts are clamped to a few lines (by design; the full text is one click away), so at very
  large text sizes less of the excerpt is visible.
- At 200% text on a 320 px wide viewport (an extreme combination) the Gym page and the settings theme buttons still
  scroll sideways by a few pixels; at 375 px and wider nothing overflows.
- Repeated generic labels ("Title", "Description") in the weekly editor rows are distinguishable only by position.
- Entry text is shown in the page language context; `lang` is not set per entry (language of parts, 3.1.2).
- No axe or Lighthouse run (no third-party downloads); the in-page checker is a partial substitute. Windows
  high-contrast mode and browser zoom above 200% on desktop widths were not checked.
